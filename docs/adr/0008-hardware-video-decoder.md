# ADR 0008: Hardware Video Decoder Backend Selection

## Status
Accepted

## Context
Milestone 2 requires implementing a native Windows hardware video decoder capable of ingesting H.264 elementary streams (generated by Milestone 1's NVENC encoder) and producing decoded frames directly in GPU memory for Direct3D 11 presentation.

Two primary architectural options were evaluated for this milestone:
1. **Option A: NVIDIA NVDEC API** via the NVIDIA Video Codec SDK (`nvcuvid.dll`).
2. **Option B: Native Windows Direct3D 11 Video Decoder API** utilizing Direct3D 11 Video Device infrastructure (`ID3D11VideoDevice`, `ID3D11VideoContext`, and the Windows D3D11 Hardware Video Transform / DXGI Device Manager).

---

## Detailed Evaluation Matrix

| Architectural Criterion | Option A: NVIDIA NVDEC (`nvcuvid`) | Option B: Direct3D 11 Hardware Decoder (Selected) |
|---|---|---|
| **Hardware Compatibility** | Exclusively NVIDIA GPUs (GeForce GTX/RTX, Quadro). Fails on AMD and Intel hardware. | Universally supported across **NVIDIA** (via GeForce D3D11VA), **AMD** (via Radeon D3D11VA), and **Intel** (via Intel Graphics D3D11VA). |
| **Client Workstation Profile** | Restricts client to NVIDIA desktops. Unusable on common client laptops with Intel iGPUs or AMD APUs. | Excellent for client endpoints: seamlessly runs on heterogeneous client hardware without vendor lock-in. |
| **D3D11 Surface Interoperability** | Decodes to CUDA video memory (`CUdeviceptr`). Presenting on D3D11 requires CUDA-Direct3D interop (`cuGraphicsD3D11RegisterResource`), adding cross-API driver complexity. | **Native D3D11 Surfaces:** Decodes directly into native `ID3D11Texture2D` NV12 surfaces allocated on the client's `ID3D11Device`. |
| **GPU Memory Copies** | Non-trivial: requires CUDA-to-DirectX resource mapping and synchronization, or intermediate memory transfers. | **True Zero-Copy:** Decoded textures remain in VRAM on the presentation device and are directly bound to the swapchain render pipeline. |
| **Device Ownership** | Split ownership: separate CUDA context (`CUcontext`) and Direct3D 11 device (`ID3D11Device`). | **Unified Ownership:** The same `ID3D11Device` is authoritative for hardware decoding, color processing, and swapchain presentation. |
| **Synchronization Overhead** | Requires inter-runtime fence synchronization between the CUDA driver queue and the DirectX 11 command queue. | Native DirectX 11 GPU pipeline ordering. Zero cross-runtime synchronization penalties. |
| **SDK & Header Dependencies** | Requires proprietary NVIDIA Video Codec SDK decode headers (`nvcuvid.h`, `cuviddec.h`) and CUDA runtime availability. | Standard Windows platform headers (`d3d11.h`, `mfapi.h`, `mftransform.h`). Zero external proprietary SDK dependencies. |
| **Runtime Capability Detection** | Queries `cuvidGetDecoderCaps`. Driver must expose CUDA driver entry points. | Queries `ID3D11VideoDevice::GetVideoDecoderProfileCount` and `MFTEnumEx` for hardware video decoders. |
| **Debugging Complexity** | Multi-runtime debugging (CUDA debugger + Visual Studio Graphics Diagnostics). | Single-runtime debugging: PIX for Windows, RenderDoc, and Visual Studio Graphics Diagnostics fully support the pipeline. |

---

## Decision

**Select Option B: Native Windows Direct3D 11 Hardware Video Decoder.**

1. **Vendor Neutrality for Client Workstations:** While the host engine leverages NVIDIA NVENC for specialized low-latency hardware encoding, the client must run on arbitrary Windows endpoints (NVIDIA, AMD, or Intel). Direct3D 11 Video provides universal hardware decoding support across all modern GPUs.
2. **Zero-Copy D3D11 Texture Pipeline:** The decoder directly produces `ID3D11Texture2D` NV12 surfaces allocated through the DXGI Device Manager on the client's `ID3D11Device`. This eliminates any cross-API translation or intermediate GPU staging buffers.
3. **Hardware Acceleration on Target Hardware:** On our benchmark machine (GTX 1660 SUPER), the Direct3D 11 hardware decoder engages the NVIDIA Turing NVDEC engine directly via the driver's D3D11VA implementation, achieving identical decoding performance to raw NVDEC without the CUDA dependency.

---

## Consequences
- Guaranteed zero CPU readback for decoded frames.
- Seamless interop with the Direct3D 11 presentation engine.
- Complete hardware portability for future AMD and Intel client devices.
